# 研究结论与已排除的方法

[English](../en/10-RESEARCH-FINDINGS.md) · [文档目录](README.md)

## 证据的阅读方式

本文针对第一代 Middleton / LENNOX，以及[补丁规范](01-FIRMWARE-PATCHES.md)所标识的 17.0.37 输入。它汇总研究结论，不是通用刷写配方。生产代码分析、协议观察、参考 SDK 定义和待实现方案具有不同的证据强度。公开仓库不包含原始设备日志和专有二进制，因此不能仅凭公开源码独立复现下述全部历史观察。

## 可避免重复探索的结论

| 调查过的方法或假设 | 结果与可复用结论 |
|---|---|
| 复用其他机型的 TA OTA / FA302D24 路径 | Middleton 已确立的路径是 BLE GAIA / VM Upgrade；同一品牌不等于协议兼容。 |
| 将 PS `0x009D` 当作升级状态 | 错误：已确立的升级上下文是 PS4。PS9D 损坏与蓝牙音频失效有关，但各字段含义仍未确定，见[持久化配置](09-PERSISTENT-CONFIGURATION.md)。 |
| 根据 STORE 请求长度推断实际存储长度 | 本目标的处理需要填充并完整读回；不能将 PS4 编码推广到任意键。 |
| 等常规认证失败后再续传 | 一次修改版完整镜像尝试返回 `003d`，主机清理前上下文已丢失。支持的暂存路径停在 footer 之前，不是从通常的签名拒绝中恢复。 |
| 直接跳到 resume 2 | 会跳过必要的复制路径。支持的路线使用受约束的 PRE_VALIDATE/resume 1 转换，见[校验与恢复](02-UPGRADE-AND-VALIDATION.md)。 |
| 重算校验和或套用其他产品的签名方法 | CRC/XOR 重封装不能替代 RSA-PSS 认证。未取得签名私钥，修改版也没有重新签名。 |
| 用修改后的显示版本证明 MCU 行为 | QCC 显示标记与 MCU 电源策略修改相互独立。版本读回是身份依据，不证明每项 MCU 修改均正确执行。 |
| 假定所有试启动失败都能恢复 | 曾观察到试启动超时回退，但不能证明任意固件修改后均可恢复。 |
| 将“全部字节已发送”等同于无线传输量 | 部分历史游标统计包含跳过区段，应分别记录已确认发送量、设备请求的跳过量和逻辑镜像游标。 |
| 通过迷你容器缩短安装 | 此类实验探测了解析/校验行为，未建立安全的短包刷写或官方回刷方法。删减分区不是已验证的优化。 |
| 仅根据 MTU 增大分块 | 45 字节探测能继续，55 字节探测停滞，原因未明；这不是 BLE 物理上限。见[传输吞吐](03-BLUETOOTH-AND-WINDOWS.md)。 |

## 官方 Android App 声音控制分析

静态分析使用的 APK SHA-256 为 `09ebe8831b92f17f881bfb5b6060b3e122cfc893b1137a7fe5ca5d2603010ef7`，来源记录为 APKPure。本次分析未独立验证其发布者签名。结论仅适用于该文件中已追踪的 Middleton 分支，不代表商店最新版或 iOS 应用。

- `PlayerViewModel` 与 `BLEDeviceStateController` 主动请求初始音量读取，并合并读取结果与通知。Middleton 使用 legacy `aa08`，合法零值会保留；已追踪路径中未发现暂停播放时切换的另一条“真实音量”接口。
- 官方写入路径先更新本地状态，再排队写入 GATT。因此 UI 目标值不能证明设备已采用该值。单次反馈抑制标记也不是交互期间丢弃全部通知的通用过滤器。
- `TwoBandEQViewModel` 经 `aa16` 使用两段 EQ 路径，从本地状态保留另一频段。扩展编码为 `bass FF FF FF treble 00 00 00`；本地状态过时可能覆盖另一频段的新变化。
- 已追踪 wrapper 的默认参数选择 100 ms `throttleLatest` 窗口：首值立即发出，后续值合并；不是等待操作结束的 debounce。排队写入与通知仍不提供独立的 MCU 生效确认。
- 官方通用 EQ 解码器对非法数据回退为全零对象；Silver Moon 将畸形数据视为未知，避免把它显示成合法设备上报。

这些分析解释了交互响应方式，但未建立播放前合法 `aa08=00` 上报的修复办法。当前行为与支持范围见[蓝牙与 Windows](03-BLUETOOTH-AND-WINDOWS.md)。

## 可配置休眠：已定位扩展点，尚未实现

已发布 r2 补丁抑制两处已定位动作，没有实现可调整的休眠时间或新的 BLE 设置命令。现有 GAIA timer 尚未被证明可替代 MCU 的 AUX 与十分钟路径。

对于文档 01 所述 STM32 应用映射，以下位置可作为后续研究入口：

| 位置 | 静态观察 | 尚需解决 |
|---|---|---|
| `0x080134b8` → `0x080129d4` | 按 CR/LF 收集文本并分发 | 安全扩展、消息边界及生产路由 |
| `0x08014384` | 独立的 `0xCC` 二进制分支 | 帧语义；不能与文本命令互换 |
| `0x08011f44` → `0x08014d66` | 逐字符发送路径 | QCC 端到端确认处理 |
| `0x08016054` | 发送 `AT+WIRE=48000` 或 `AT+WIRE=0` | 不证明主机能够任意控制 MCU |
| `0x0801c42c` → `0x080210e6` | 已有升级标记存储用途 | 存储归属、介质和空闲空间映射；设备索引 8 不是已证明的 flash 页 8 |

`READY`、`ABSV`、`AUDIO`、`AMP=`、`OTA=`、`MUSIC=` 等字符串有助于定位内部处理器，但存在这些字符串不等于能从 BLE 调用它们。QCC 反汇编偏移 `0x12a3e` / `0x12a70` 指向 `0x1f77c` 的发送路径，其 ABI、缓冲区所有权和自定义回复路径仍待确认。这些偏移属于所研究的反汇编，不是主机文件偏移或通用地址。Huada 接收器、确认和存储映射需独立分析。

未来的一种设计是由 QCC 保存经过校验的配置，将带版本的 RAM 副本同步给 MCU，并明确区分请求、保存、生效状态，加入能力协商。目前未确定可用 PS 键、安全的 MCU 存储分配或完整自定义消息链。该建议不是现有安装规范。修改共享关机计数还会影响复位语义；直接把 600 换成新数字不是已验证的可配置时间实现。

## Windows 与完成状态的解释

发现、绑定、加密 GATT 访问、升级完成和日常控制就绪是不同状态。扫描中的两个名称可能来自过期/轮换地址或不同设备，不能仅凭名称判定身份。成功读出型号不证明有权访问受保护的声音特征。

重启后反复读取相同 PS4 不算进展。安装完成需要文档 02 所述协议与独立读回依据。日常控制服务可能稍后才就绪，应独立恢复，不能重放已完成的安装。尚未建立开机音效播放完毕的信号，蓝牙可达不证明开机音效已结束。

继续研究时，应保留精确输入哈希、地址空间、请求/回复编码与失败结果。未经验证的假设应明确标记，不能直接写成公开操作指南。
