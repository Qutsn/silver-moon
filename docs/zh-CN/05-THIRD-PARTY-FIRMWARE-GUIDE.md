# 第三方安装规范：middleton-mcu-v1

[English](../en/05-THIRD-PARTY-FIRMWARE-GUIDE.md) · [文档目录](README.md)

当前实现将文件检查与安装策略联动：已知官方/r2 包维持原策略；未知文件必须通过本规范才可进入安装确认。不符合时给出原因，安装按钮不可用，协调器也独立复核。此能力已实现离线验证，不代表第三方包已经实机验收。

## 允许的修改

以项目 r2 完整包为基准（SHA-256 `80ed2088247976f10968f5d4aefb3cabf367ff0b0a1f774ac6e62a292c459024`），仅允许等长修改下面两个嵌入文件。偏移均为完整包内从零开始的字节偏移，终点不包含在范围内。

| 文件 | 起点 | 长度 | 终点 |
|---|---:|---:|---:|
| huada.bin | 2445564 | 128980 | 2574544 |
| mcu.bin | 2574544 | 138872 | 2713416 |

两个区域相邻，允许区间为 `[2445564,2713416)`。作者可以修改这里的 MCU 程序，但须自行处理 MCU 内部校验、启动和功能正确性。软件不保证任意机器码能运行。

整个文件必须为 3,266,308 字节。以下两段必须与基准完全一致；实现通过 SHA-256 核对，不相信文件名或作者声明：

| 受保护区间 | SHA-256 |
|---|---|
| `[0,2445564)` | `c14433030a3b862dc04e8a6b5079e95a8ca0e7a90445717854cc7f57f7843614` |
| `[2713416,3266308)` | `c09c70c2cb0c6536428a44b0363f227f56ca83345e8d98bf05a57866e22636d4` |

这同时锁定完整头部、QSPI/分区元数据、文件系统目录、非 MCU 资源、QCC 蓝牙升级程序、r2 版本显示代码和尾部。v1 不允许修改蓝牙主程序、分区尺寸或文件目录；这样的包需要未来新规范与新策略。

## 容器约束

记录包含 8 字节 ASCII 标识、4 字节大端内容长度和内容；必须无截断、无尾部多余数据。

头部芯片标识为 QCC512Xx。尾记录起点为 3266040。导入还有 16 MiB 读取上限。单独通过容器检查不足以安装，还必须满足上述受保护区间。

## 从制作到安装

1. 合法取得指定 r2 基准，核对完整 SHA-256；不要从不可信链接获取所谓兼容包。
2. 修改两个 MCU 文件内需要的字节，原位写回，保持长度。不得重新排布文件系统或改动其他区域。
3. 在软件选择本地 `.bin` 文件。软件计算成品 SHA-256 和该文件自己的协议 image ID，显示符合规范或拒绝原因。
4. 用户确认刷入后，程序重新读取文件并检查哈希，防止选择后文件被替换；连接后再核对 Middleton 型号、硬件 3.0.2 和当前已支持的版本。
5. 使用 staged 策略传输到固定分区边界，按新文件 image ID 核对暂存状态，仅修改已验证恢复字段；断线后由设备重新指定偏移。
6. 试启动、提交、断连及重新连接后的版本/空闲状态核对通过，才报告协议安装完成。

无需额外 manifest 文件；v1 的型号、布局和显示版本由受保护内容固定。成品 SHA-256 是每个第三方包的身份，恢复记录按实际哈希隔离，不复用 r2 的固定 image ID。

## 成功与验证边界

v1 保留 r2 的 QCC 版本显示，所以详情页仍显示 **25.2.52**，不是第三方作者自定义版本。该字符串只能证明保留的 QCC 版本标记，不能独立证明 MCU 内部升级成功或功能正确；记录和确认界面中的完整 SHA-256 区分不同包。

结构通过允许尝试安装，不保证设备必然接受，也不保证被修改 MCU 可启动。程序不会用传输 100% 冒充安装完成；设备拒绝、身份不符或提交握手失败时停止并保留记录。此规范没有修复厂商签名，也不是通用任意分区写入器。

测试覆盖受保护边界被改动的拒绝、两个 MCU 区间的准入、独立 image ID、完整模拟传输、丢失 ACK 后由设备指定续传位置和最终重启读回。离线测试不保证任意第三方固件可安装、启动或正确运行。

## 规范用语与身份计算

本规范的“必须”表示当前代码执行的准入条件，MCU 启动/功能正确性等作者责任除外。可执行定义见 [ThirdPartyFirmware](../../glass-playground/Domain/ThirdPartyFirmware.cs)、[FirmwareContainer](../../glass-playground/Domain/FirmwareContainer.cs)、[FirmwareCatalog](../../glass-playground/Domain/FirmwareCatalog.cs)。

每份完整文件的协议 image ID 为 MD5 摘要的最后四个字节，不是认证机制；文件完整 SHA-256 才是主机端身份与记录隔离依据。staged 路径当前版本门控为 17.0.37 或 25.2.52，硬件必须是 3.0.2。测试见 [ThirdPartyFirmwareChecks](../../tests/DesktopReadOnly/ThirdPartyFirmwareChecks.cs) 和 [ResumableUpgradeChecks](../../tests/DesktopReadOnly/ResumableUpgradeChecks.cs)。材料依赖测试需要精确基准文件，不能以缺料跳过结果代表通过。
