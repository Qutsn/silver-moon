# 修改版安装、校验与断点恢复

[English](../en/02-UPGRADE-AND-VALIDATION.md) · [文档目录](README.md)

本文说明 Middleton 已研究版本上的机制，不是任意型号、任意分区的通用刷写方法。它整理了项目早期实验与当前桌面实现，未发布原厂二进制或私人设备日志。

## 是否“跳过了固件校验”

准确说法是：修改版采用分区暂存与恢复状态流程，绕开正常完整包传输末尾的 RSA-PSS 验签入口；后续分区验证、复制、试启动、提交和读回仍存在。

正常更新完整接收 APPUPFTR 后校验分区内容。已修改的 r2 完整包在普通流程中曾返回 `003d`（OEM footer 验证失败）。此时升级上下文已清理，因此不是“先让验签失败，再强行继续”。

已验证的路径在所有镜像分区关闭、但尚未发送 APPUPFTR 时停止。升级恢复状态位于 PS key `0x0004`。严格核对暂存进度和映像身份后，只改已研究的 PRE_VALIDATE 恢复字段；普通重启后进入分区验证与 ImageUpgradeCopy 路径，而不重走前面的完整包 RSA 验签入口。

这没有取得厂商私钥、没有产生有效的新签名，也没有修改正在运行的升级库验签函数。它暴露的是升级恢复状态的信任边界；不能据此认定启动链没有其他校验，或任意固件都能启动。

## 当前实现保留哪些检查

1. **文件准入**：已知原版/r2 必须匹配完整 SHA-256。第三方文件必须满足固定布局、长度和受保护区间哈希，不能只改扩展名。
2. **精确分区边界**：完整文件为 3266308 字节；APPUPFTR 起始为 3266040。修改版传输停在该边界，还要核对设备随后请求 12 字节记录头及实际 PS4 状态。百分比达到 100% 不是证明。
3. **状态与身份**：核对型号、序列号、映像 ID、版本及恢复状态。保存 PS4 原内容，仅修改所需字段并完整读回；不能盲写整个上下文。
4. **后续验证与提交**：重启、恢复验证、试启动、提交、完成通知，以及重新连接后的预期版本/空闲状态读回共同决定成功。

官方回刷采用正常全量上传流程；修改版恢复路径与官方路径不可混为一谈。具体约束以源码为准，不建议手动照抄状态写入值。

## 为什么断线恢复不会只看本地进度条

BLE 的 ATT 写入成功、GAIA 命令 ACK、升级完成是不同层次。客户端逐帧等匹配的 ACK；重连后重新 SYNC 并核对设备状态，由设备的数据请求决定传输位置，而不是把 UI 百分比换算成文件偏移直接继续。

本地恢复记录按设备及文件哈希隔离；同一设备有排他锁。记录是辅助证据，不替代设备读回。累计 ACK 字节可包含重传，不能当作唯一字节覆盖量。超时、身份不符或协议不一致必须停下，而非把传输完成显示为安装成功。

文件 SHA-256 校验说明“我们准备的是哪一份文件”，不等于对设备内部每个写入字节进行了独立读回。最终仍依赖设备协议验证、提交结果和实际功能测试；这也是第三方代码兼容性无法由桌面程序保证的原因。

## PS4 的编码与字段修改约束

[UpgradeContext](../../glass-playground/Domain/UpgradeContext.cs) 只接受 38 字节，即 19 个大端 16 位字。以下是该 Middleton 路径的项目语义，不是通用 CSR 格式。

| 字段 | 当前解释 |
|---|---|
| 映像 ID | 先 word 12、后 word 11，各四位十六进制 |
| 恢复状态 | word 13 |
| 最后关闭分区 | word 14 |
| 暂存分区完成 | 映像 ID 匹配；word 14=10、word 7=5、word 8=2 |
| 空闲 | 映像 ID 为零，word 13、14、7、8、9 均为零 |

准备验证还要求 resume=0，word 0–3 为 0x8003、5、2、1。STORE_PS_KEY 负载共 78 字节：2 字节 key、完整 38 字节值、38 字节 mask 区域。值中仅 word 13 改为 1。CheckPrepared 将整个读回结果与原始值只改这一字后的结果比较；这些是实现的防护条件，不是允许手工盲写 PS 的接口。

## 协调器状态与超时

| 恢复状态/本地证据 | 行为与必要证据 |
|---|---|
| 0 | SYNC/START 后按设备请求传输；staged 路径在 footer 前停止 |
| 1 | 必要时核对已准备状态并复位，随后轮询验证 |
| 2 | 核对映像 ID 和恢复状态，发送试启动响应并重连 |
| 3 | 核对显示版本，发送继续响应并要求消息 15 |
| 3 或 4 | 发送提交响应，要求消息 18（COMPLETE_IND） |
| 已保存 CompleteInd | 观测断连；重连后要求预期显示版本及空闲 PS4 |

大于 4 的恢复状态被拒绝。staged 数据阶段之后还要求本地分区边界证据和设备暂存分区匹配，不能仅凭设备非空闲就接管。

孤立或不匹配的旧上传只允许在 resume=0 时替换：发送 ABORT（7），要求确认（8），读回空闲 PS4，发送 GAIA 升级断开 0x0641，重置记录并建立新传输。不会自动中止验证、试启动或提交阶段。

当前总时限为 75 分钟；断线/无进展恢复预算为 30 秒，含两秒退避；验证及最终断连等待分别为 180 秒，提交完成等待为 300 秒。重复读到相同 PS4 不是进展；相关阶段或最高确认位置前进才更新恢复预算。超时保留记录，不报告成功。

观测最终断连后固定等待三秒，再建立新连接核对版本与空闲状态。该等待并不是开机音效结束的证据，当前没有接入相应信号。

## 请求游标的计算

每次 Transfer 会话从 cursor=0 开始。设备请求解析为 count、skip，计算 start=cursor+skip、end=start+count；count 必须非零，边界不能超出当前策略上限。每块最多 45 字节，成功 ACK 后才推进 cursor 和累计 ACK 字节，skip 单独统计。闪存写入可能在 ACK 丢失前已生效，因此新会话不能盲目使用本地最高确认位置作为续传点。

本地锁只在当前用户日志目录内按设备排他，不跨电脑仲裁。源码、模拟测试与实机证据的区别见[证据与验证](08-EVIDENCE-AND-VERIFICATION.md)。
