# 证据分级与可复现验证方法

[English](../en/08-EVIDENCE-AND-VERIFICATION.md) · [文档目录](README.md)

## 目的

本系列是工程研究文档，不代表已经通过同行评审，也不是完整的厂商协议规范。每项技术结论都应说明适用映像、设备条件、证据类型和局限；精确的数值表格本身不能把推断变成已验证事实。

| 证据类别 | 可以证明的内容 | 不能据此证明的内容 |
|---|---|---|
| 源码约束 | 具名函数及其检查明确实现的行为 | 所有实体设备都符合程序假定的协议行为 |
| 离线测试 | 对给定模拟或精确文件样本的程序行为 | 实体闪存内容、实机运行成功 |
| 逆向分析 | 指定二进制与地址映射上的控制流、数据流解释 | 未知版本或未公开 bootloader 的通用规范 |
| 协议观测 | 给定条件下读到的消息与状态 | 每个内部写入字节、其他电脑上的未来行为 |
| 实机功能测试 | 指定设备、映像和场景中的可观察功能 | 普遍兼容性或无其他回归 |

## 文件层面的复现

记录源码提交、构建参数、OS/SDK 版本、输入长度及完整 SHA-256。官方/r2 身份见 [FirmwareCatalog](../../glass-playground/Domain/FirmwareCatalog.cs)；补丁偏移和原字节前置条件见 [FirmwarePreparation](../../glass-playground/Application/FirmwarePreparation.cs)。

持有精确支持的输入文件时，可独立检查容器长度与记录、逐字节比对补丁跨度、核对 r2 成品哈希，以及验证第三方准入的受保护前后缀哈希。仓库不包含固件素材；缺少素材的测试必须标记为跳过，不能记为通过。

从仓库根目录运行源码模式检查与构建：

```powershell
./glass-playground/check-localization.ps1
./tests/DesktopReadOnly/test.ps1 -WithoutFirmwareMaterials
./glass-playground/build.ps1 -WithoutBundledFirmware -CompressSingleFile -OutputDirectory publish-review
```

测试/构建脚本可能退出调用进程，应分别启动 PowerShell。`SilverMoon.exe --portable-smoke <report-path>` 检查便携包、资源和子进程启动，不执行 BLE 操作，不能当作配对或安装测试。

## 协议测试设计

分别覆盖 ACK 前后断线、PS4 不变的重复重连、错误设备/映像身份、越界数据请求、旧通知、取消和未观测重启的完成路径。检查失败时是否保留记录并停止，而不是推断成功。

必须区分请求游标、跳过字节、累计 ACK 字节、最高确认位置与设备恢复状态。每个测试应说明预期失败方式。总是返回预设成功事件的模拟传输不能验证实机恢复。

## 实机验证记录

有效报告应包含型号/硬件、初始与目标固件身份、Windows/蓝牙适配器配置、音源与播放状态、操作顺序、中断点、协议观测、完成证据及功能结果。共享时使用脱敏标识，不公开真实串号、用户名或个人路径。关闭电脑蓝牙、退出应用和音箱断电并不是等价的中断实验，应分别记录。

当前协议完成判据是提交完成、观测断连、再通过新连接读到预期版本及空闲状态。功能验收另外检查 AUX、自动关机、播放、声音控制及适用的官方回刷行为。QCC 显示标记不能单独证明 MCU 已被替换；当前接入的信号也不能证明开机音效已经结束。

## 公开证据与翻译维护

公开源码和测试支持实现审阅，但未附带原始反汇编材料及私人日志。依赖这些材料的语义应标为研究结论，不应写成仅凭源码即可独立重现。文档不暗示已经通过外部同行评审、完全安全或普遍兼容。

同一编号的中英文文档应在同一次修改中维护，保持哈希、字节序、偏移、不等式、检查条件和不支持情形一致。可执行行为以当前源码为准；发现翻译差异应修正两份，不能默认采用限制更少的表述。根目录旧文档路径保留为语言入口，兼容已有链接。
